# Market Test Protocol

## Objective

Test whether users voluntarily request an independent transparency check without outbound sales.

## Variants

### A — Quote Benchmark
Need: offers are hard to compare because scope, assumptions and exclusions differ.

### B — Surplus Value Check
Need: owners do not know which surplus positions are worth researching or selling.

### C — Benchmark the Benchmark
Need: users do not fully trust a portal ranking or cannot tell whether the displayed result is economically best.

## Funnel events

1. Landing-page visit
2. Pilot CTA click
3. Qualified pilot request
4. Case accepted
5. Useful result delivered
6. Requester asks for / accepts paid follow-on
7. Revenue or transaction support starts

## Evidence hierarchy

Strongest to weakest:
1. paid follow-on / paid transaction support
2. willingness to share real non-public data through a secure channel
3. qualified inbound request
4. CTA click
5. page visit
6. social engagement

Likes, impressions and compliments are not product-market validation.

## Phase-0 success gate

Continue investing only if the test produces:
- >= 5 qualified inbound pilot requests, and
- >= 1 requester willing to pay for follow-on analysis or transaction support.

Otherwise revise positioning or kill the variant before building a backend.

## Cost rule

Cash spend = EUR 0 until the Phase-0 success gate is met.

Allowed:
- GitHub Pages
- GitHub Issues for non-sensitive intake
- AI-assisted manual analysis
- public web research
- existing software/accounts

Not allowed before validation:
- paid ads
- paid data feeds
- custom SaaS backend
- inventory purchases
- paid domains
- automated regulated recommendations

## Safety / trust rules

- Never infer certainty from incomplete market data.
- Separate observed facts from estimates.
- State data coverage and missing sources.
- Never rank based on compensation.
- Keep monetization logic independent of analytical ranking.
- Never publish confidential client inputs in GitHub Issues.
